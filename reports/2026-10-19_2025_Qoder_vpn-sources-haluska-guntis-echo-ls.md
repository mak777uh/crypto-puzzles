## 1. VPN: recipe (важно для дежурных прогонов)

- Подписка (токенизированный URL от Ильи) → base64 с 7 строками `vless://`; конфигурация Xray лежит
  в `%LOCALAPPDATA%\Temp\vpn\cfg_3.json`, **вне репозитория каталога** (правило: креды в каталог не пишутся).
- Бинарник: Xray-core v26.3.27 (`Xray-windows-64.zip`), sha256 сверен с официальным `.dgst` — совпало.
- Из 7 узлов с этого хоста TCP проходит только `ams5.vpntype.dev:8443` (VLESS+REALITY,
  flow `xtls-rprx-vision`, fp=safari, sni=ams5.vpntype.dev).
- Старт: `/tmp/xray/xray.exe -c /tmp/vpn/cfg_3.json` → HTTP-прокси `127.0.0.1:10809`; egress `147.45.221.58`.
- Использование: `HTTP_PROXY=http://127.0.0.1:10809 HTTPS_PROXY=http://127.0.0.1:10809 python <скрипт>` —
  `urllib` подхватывает переменные сам, менять код не требуется.
- Ограничения, измеренные сегодня: `web.archive.org` через egress VPN = **503** (напрямую — 200),
  поиск bitcointalk (`action=search2`) гостю недоступен даже через VPN (только чтение топиков по URL).

## 4. echo.ls — второй разбор того же solver

- `zden-level-5`: живой и полный (формула `x=(10·width+left−1)/64`, `y=(10·height+top−1)/64`,
  8×8 матрица площадей, суммы пар подряд идущих → 32 байта, адрес из **uncompressed** pubkey =
  `1cryptoGeCRiTzVgxBQcKFFjSVydN1GW7`). HALV-переносимость слабая: HALV — волна (grayscale 950×950,
  s(x)), не прямоугольники; автор про HALV написал «way easier than LVL 5». Ось как прогон
  не регистрируется — нет сужающего правила с доказательной базой (правило №4).
- `cipher-in-circles` (05.10.2026): Crypto Puzzlers, 69 состояний → Брайль → сегментация по паттерну
  outer/middle/inner → 12 BIP39-слов → `m/44'/60'/0'/0/0`. В нашем каталоге папки нет; баланс
  опубликованного адреса `0x98EaBa52eF74a9c52CC2B34cD96d7FA19537eC6E` = 7,7e-09 ETH ≈ 0 →
  **не новая цель**. Методическая ценность: второй случай, где LLM-агент сам подобрал простую
  формулу к визуальной схеме.
