- Задача (правило Ильи от 18.10.2026): агент, который берёт в работу базу или отдельную загадку,
  сначала собирает на GitHub всю информацию по неё из репозиториев. Формулировка уточнена через
  вопросы владельцу: шлюз строгий (без него — ни строки в `PROPOSALS.md`, ни проверочного прогона;

## 4. Отрицательные результаты и ограничения

- Шлюз ещё не пройден у 75 из 80 активных папок; очередь — `_sources/github/INTAKE_BACKLOG.md`
  (80 строк, ~API оценивается по числу кандидатов). У ~40 папок github-ссылок нет вообще — для них
  шлюз закрывается веткой `none` за 0 запросов, иначе правило заморозило бы всю базу.
- Анонимный `search` = 10/мин и только по названию, GraphQL анонимно недоступен, поэтому «репо
  автора по косвенным признакам» ищется таблицей известных авторов + `/forks`, а не поиском.
- `--api-budget` не покупает содержимое: контент реп бесплатен, но `issues/comments/PR/releases/gists`
  требуют бюджет; для «кипяточников» вроде GSMG 14 запросов на репо с 112 issues — норма.
- Дайджест не переводит и не проверяет чужие утверждения: раздел «новое против нашего досье» — это
  «требует проверки», а не подтверждение.
- Не проверялось на приватных репозиториях и на репо с LFS-ассетами; токенов GitHub в базе нет.
- Перекрёстное обнаружение (§3.11) работает по имени: папка вида `<owner>__<repo>` и токен в имени
  файла отчёта. Оно не найдёт репозиторий, о котором в базе нет ни следа (для этого остаются
  `--search`, `/users/<owner>/repos` и внешний `tools/github_broadrepo_scan.py`), и может дать
  ложного кандидата, если соагент назовёт папку по своей схеме — кандидат стоит 1 бесплатный
  `ls-remote`, поэтому риск дёшев, но список надо читать глазами в разделе «Негативы» дайдеста.
