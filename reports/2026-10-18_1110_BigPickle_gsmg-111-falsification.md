## Протокол прогона (что именно проверяли)

Ось была задана формулами issue #111 (`0xyph3r`, 05.09.2026) — единственной публичной

## Результаты

### 1. `gros` воспроизведён — и он оказался «правильным»
- Блоб Phase 3.2 из `data/puzzlehunt/README.md`: 2448 B = `Salted__` + salt `eefc4c5befc1656a` + **2432 B ct**.
- Расшифровка AES-256-CBC, EVP_BytesToKey **SHA-256** (важно: `D_i = H(D_{i-1} ‖ password ‖ salt)`,
  без соли не работает), пароль `sha256("jacquefrescogiveitjustonesecondheisenbergsuncertaintyprinciple")`
  → **2422 B plaintext** `gros`, sha256 `b82afeb86f9e50848220f9b64b744b821400308aea273a1c949b9d2d0e408a34`.
- Структура `gros` (offset): Архитектор-речь **0**, `... am I here` 336, `One for one, four for one` 417,
  конец ASCII-речи **447**; **Beaufort-блок 447–1986 (ровно 1539 B, 26 символов)**; CRLF 1986–1990;
  149-значный числовой поток 1990–2143; подсказка `Raising the stakes…` 2143–2292; внутренний blob 2292–2422.
- Внутренний blob: 48 B, salt **`b45a5e3d827593ca`** (совпадает с salt из #111) → расшифровать его
  мешает неразгаданная фраза подсказки «without extra chances of winning».
- Разметка Beaufort-блока **байт→буква восстановлена и совпала с буквенной транскрипцией README
  символ-в-символ** (26 байт ↔ 26 букв, конфликтов 0) → наш `gros` идентичен тому, с которым
  работает сообщество. Инструмент: `tools/gsmg_phase32_gros_repro_2026-10-18.py`.

### 2. Установлен важный стратегический факт: публичный ключ приза ОПУБЛИКОВАН
- `04f4d1bbd91e65e2a019566a17574e97dae908b784b388891848007e4f55d5a4649c73d25fc5ed8fd7227cab0be4e576c0c6404db5aa546286563e4be12bf33559`
  (uncompressed, точка на кривой) → `hash160 = a9553269572a317e39f0f518cb87c1a0ee1dbae4`
  = **ровно адрес приза `1GSMG1JC9…`** (проверено; совпадает с H160-«целью» из #111).
- Следствие: любой кандидат приватного ключа проверяется **мгновенно и офчейн** (pubkey == `04f4d1bb…`),
  без запросов к блокчейну. Это надо использовать во всех будущих прогонах по GSMG.

### 3. Константы #111 **не воспроизводятся** — ось закрыта негативом
- `FH = gros[0::4][:16] XOR gros[1145:1161]` на нашем `gros` = `801e5053aeb04a50a953e92c3501a330`,
  а #111 заявляет `8048c428a6faf6d3df77db13ca68766d` — **не совпадает**.
- `gros[1161:1177]` = `c0d12ff6cc5fcac05f5f3ec960c2c5c8`, #111 заявляет `3be6ecf1d5c126e50f25ded3bc8fb6d9` — **не совпадает**.
- **Исчерпывающий поиск (дёшево, только XOR):** ни в одном из 7 буферов (plaintext 2422, ct 2432,
  full 2448, буквенный блок 1539, `speech+letters+tail`, речь 447, внутренний blob),
  ни при одном stride 1–8 и ни на одном смещении 16-байтные XOR-пары **не дают** `FH` из #111 → **0 совпадений**.
- Вывод: `gros` в #111 = **некий 2432-байтный артефакт, который он не раскрыл**. Его «First Half,
  verified against H160» из публичных данных **непроверяемо**. Трактуем как неподтверждённое.

### 4. Свип кандидатов ключа: 0 хитов
- 204 кандидата: `FH`, `FH‖FH`, `FH‖g1145`, `FH‖g1161`, `sha256(FH)`, `sha256d(FH)`, `FH±1`,
  XOR-свёртки `SOURCE_4` (48 B из base64 `QvX0t8v3jPB4okpspxebRi6sE1BMl5HI8Rku+KejUqTvdWOX6nQjSpepXwGuN/jJ`)
  во всех stride/окнах × `gros[1161:1177]`, и их комбинации с `FH`.
- Проверка против публичного ключа приза и его LE-интерпретации → **0 попаданий**.

## Вердикт

Ось «приватный ключ приза извлекается из `gros` по формулам issue #111» — **ЗАКРЫТА (негатив)**.
Причина необратимая: фундамент #111 непроверяем (артефакт не раскрыт), а не «мы плохо искали».
`gros` и структура Phase 3.2 при этом воспроизведены точно — артефакты сохранены для будущих проходов.
