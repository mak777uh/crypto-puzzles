# CUDA-движки перебора из open-crypto-puzzles — указатель (НЕ собирать и НЕ запускать без отдельного решения)

Оригинал: `_sources/ocp/engines/` (клон, коммит `19644e58e50721f8469680f2edcba1daa0697630`,
2026-10-18, агент `OCP Sync`). Их `engines/README.md` — 17 КБ, там же `build.sh`, хост-драйверы
и `engines/lib/`. Это чужой код; в `MASTER/tools/ocp/` перенесены только сервисные утилиты
(`check_escrows.py`, `derive.py`, `validate.py`), движки остаются в клоне.

Статус в нашей базе: **справочный материал**. Сборка и запуск — не часть прохода синхронизации;
по `AGENT_INSTRUCTIONS.md` любой перебор требует (а) заранее зафиксированной в `LOG.md`
инсайт-оси и (б) устного/письменного ОК Ильи, ≤15 мин на прогон. Здесь просто зафиксировано,
что существует и на что способно.

## Что стоит знать до любых прогонов

1. **Раунды зашиты.** У #2 `pbkdf2_sha512(..., 2048, seed)` в горячих ядрах (строки 1689, 1767,
   1880, 2016) и у `derive.py` `Bip39SeedGenerator` (библиотека фиксирует 2048) — флага переопределения
   нет. Пазл Genesis (решён 17.10 внешним решателем) был именно про это: реальные rounds = 181505/200913,
   и 78 млн наших кандидатов при 2048 были пустыми. Любой негатив, полученный этим движком по BIP39-пазлу,
   **не покрывает** пространство нестандартных rounds — см. записи «rounds-ось» в `LOG.md` живых пазлов.
2. **Производительности несопоставимы между собой** (их собственная оговорка): #1 делает один SHA-256
   на кандидата, #2 — ~4096 компрессий SHA-512 до эллиптической кривой. Размер поиска считать по
   движку конкретной схемы, а не по максимальному числу в таблице.
3. **Этика/безопасность.** Их формулировка: движки сравнения с опубликованным автором адресом-челленджем;
   ничего не направлено против чужих кошельков. Наша дисциплина строже: только точное совпадение с
   оракулом как позитив, негативы с свидетелями, никаких транзакций и трат без ОК Ильи.
4. **Что с этим делать дальше (решение не принято).** Дешёвый путь — использовать `check_escrows.py`
   для перепроверки состояний эскроу и читать их `analysis/*` (уже разложены по папкам пазлов в
   `data/ocp/`), а сборку движков отложить: она имеет смысл только под конкретную инсайт-ось,
   зафиксированную в `LOG.md`.
